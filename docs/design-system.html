02 — Foundations

Typography

Eleven roles, each named for the job so a screen picks a role rather than a number. Two families, both from the system and neither bundled.

Rounded is what gets looked at; plain is what gets read. SF Pro Rounded carries the routine card, the page title, the exercise you are on and the figure you are lifting. Plain SF Pro carries labels, prose, controls and list rows. The split is by job, not by size.

Tracking follows the weight, not the size

Only five roles carry any tracking at all; the other six sit at a plain zero. Where it is non-zero it is written as size × ratio, so changing a size carries its tracking with it.

RoleSizeWeightTracking
label12medium+1%
heading30medium+1%

figure64bold-3%
hero82bold-1%

Medium opens, bold tightens. Size never predicted it: heading at 30 opens while screenTitle at 32 tightens.

Case belongs to the role

3 roles render uppercase — label, routineCardMeta, routineCard — while the source strings stay in sentence case. Settings really does contain "Show rest time between sets"; the role shouts it. Copy written as prose is easier to write, read and eventually translate, and the same string can be reused unshouted without being edited.

control is deliberately not among them. Uppercase button labels tracked out is Material's convention, not Apple's — iOS sets buttons in sentence case and lets SF Pro's own optical tracking do the spacing. The buttons speak rather than shout.

Dynamic Type

Every role scales with the iOS text-size setting; what differs is how far. Nothing anywhere sets allowFontScaling={false}, which would refuse the setting outright rather than bounding it.

05 — Practice

Conventions

The conventions that are not obvious from any single file, and that cost the most to rediscover.

Style with tokens, never with literals

The only literal colours in the app belong to routines, through styleFor(). Everything else is a token, which is what let a whole dark palette arrive without any component being restyled.

A routine's colour is its identity

Card, workout screen and Stats calendar all pull from the same place. A routine is not "the blue one" by coincidence — the colour is how you recognise it across three screens that otherwise look nothing alike.

Styles are a factory, not an object

StyleSheet.create runs once at import, which is before a theme exists. A themed screen therefore holds a makeStyles(t) factory called through useThemedStyles, so the sheet is rebuilt when the palette changes. A screen that calls StyleSheet.create at module scope will look correct until the moment someone switches theme.

Class names are global; so are shared files

Every regression this project has had came from the same shape: a change in a shared file breaking a screen nobody was looking at. Before changing anything shared, say which screens it reaches and what you will check — the sentence is the point.

Two failed hypotheses is a hard stop. Stop changing code and go to the history or add a measurement instead. When something that worked stops working and its own code has not changed, diff it against the commit where it worked first.

Opacity is not a colour

Fading text to imply hierarchy composites it against whatever is behind, and the result is invisible to every off-the-shelf contrast checker — they read the declared colour, not the rendered one. Quiet text uses textDim, which is a measured value.
